## Failures, diagnosis, correction and retest details

1. **Dependency restore / build environment.** Sandboxed NuGet access initially failed with NU1301 (socket access denied). Running the authorized build outside the sandbox restored successfully. A later sandbox build was denied access to Avalonia's local build-services log; the authorized build succeeded outside the sandbox. These were environment permissions, not hidden passing test results.
2. **Temporary PostgreSQL startup.** The sandbox could initialize files but could not start PostgreSQL's restricted-token subprocess. An authorized separate temporary instance started successfully on loopback port 55435. Existing PostgreSQL services and data remained untouched.
3. **First catalog attempt.** T01–T06 passed and the UI workflow assertions passed, but the runner stalled when an asynchronous continuation tried to use the stopped Avalonia synchronization context. The run was interrupted and was not called a complete pass. Resetting the synchronization context was an intermediate correction.
4. **Second catalog attempt.** Progress reached T08, where another UI invocation landed on a different continuation thread and failed thread ownership. The final correction gives Avalonia one dedicated background dispatcher thread for the process; all UI checks marshal there and signal completion back to the console thread. This preserves the production UI's asynchronous behavior and fixes only the runner lifecycle. Selected original outputs are retained in diagnostic-attempts.txt instead of duplicating two large incomplete logs.
5. **Final retest.** Complete T01–T08 passed in execution.txt, including real error screens and fault-state readbacks. A new process passed restart-readback.txt. A separate `dotnet EquipmentBorrowing.Api.dll` process returned 200 without starting Desktop and served the same OpenAPI file. The retained Lab 4 runner also passed **131 checks** in [lab4-regression.txt](evidence/lab4-regression.txt), including constraints, concurrent limit protection and the migrated UI workflows.

No supplied catalog test is marked Pass without execution. The screenshots were opened and visually inspected. They show the real compiled UI and distinct server/connection messages.
